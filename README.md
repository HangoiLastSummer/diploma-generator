# vkr — генератор ВКР по требованиям кафедры ПОВТ ПГУ

Пишешь текст в Markdown, метаданные в YAML. Генератор проверяет вход, собирает `vkr.docx` и `vkr.pdf` по методичке 2023 года и замечаниям нормоконтроля, сам вёрстает разрывы страниц.

Пользователю не нужно думать о полях, шрифтах, интервалах, нумерации глав, рисунков, таблиц, листингов, формул и источников, о подписях «Рисунок 2.1 – …», курсиве латиницы, тире, «ёлочках», пунктуации в списках, титульнике, задании, оглавлении с номерами страниц, «Продолжение таблицы N», списке источников по ГОСТ и перечне сокращений. Всё это делает генератор.

## Установка (Ubuntu / WSL2)

```bash
sudo apt install libreoffice-writer libreoffice-math hyphen-ru fonts-liberation2 pandoc
# по желанию — настоящие Times New Roman / Courier New (метрики как в Word):
sudo apt install ttf-mscorefonts-installer
pipx install ./vkr-gen        # или: pip install -e ./vkr-gen
vkr doctor                    # проверка окружения
```

## Быстрый старт

```bash
vkr init my-vkr --type web    # client-server | is | web | compute | graphics | research | project
cd my-vkr
# заполнить diploma.yaml и context/project.md
claude                        # Claude Code подхватит CLAUDE.md, хук и команды /section, /review, /build
```

Готовый пример с рисунком, таблицей, листингом, формулой, источниками и руководством пользователя лежит в `example/` (`cd example && vkr build`).

## Команды

| Команда | Что делает |
|---|---|
| `vkr check [--format json] [--file F]` | валидатор без вёрстки, ~1 с |
| `vkr fix` | безопасные правки прямо в `.md`: тире, кавычки, пробелы, регистр и пунктуация пунктов списков |
| `vkr stats` | слова по разделам против целевого объёма (≈ 270 слов на страницу) |
| `vkr build [--force] [--no-layout]` | сборка: валидатор → docx → цикл вёрстки через LibreOffice → `vkr.docx`, `vkr.pdf`, `report.md`, `report.json` |
| `vkr preview --pages 12-14` | PNG страниц в `.vkr/preview/` (чтобы Claude посмотрел вёрстку) |
| `vkr hook post-edit` | хук Claude Code: проверяет изменённый файл, ошибки возвращает Claude |
| `vkr rules E8` | текст правила из RULES.md |
| `vkr doctor` | проверка LibreOffice, Math, переносов, шрифтов, pandoc |

## Как устроено

Правила (RULES.md) разделены по моменту, когда их можно проверить, и каждый класс закрывает свой компонент:

1. **Валидатор** (`validate.py`) — всё, что видно по тексту: ссылка стоит до рисунка, пункт кончается текстом, аббревиатура объявлена и раскрыта, листинг не длиннее половины страницы, источники процитированы, нет ручной нумерации.
2. **Билдер** (`builder.py`) — гарантии построением: стили, поля, нумерация, подписи, курсив латиницы, неразрывные пробелы, титульник, задание (ФИО в дательном падеже склоняется само), перечень, источники по ГОСТ Р 7.0.11.
3. **Цикл вёрстки** (`layout.py`) — то, что зависит от разрывов страниц. Docx рендерится через LibreOffice в PDF, PDF анализируется, билдер получает подсказки и собирает заново, пока результат не перестанет меняться (обычно 3–8 проходов, 20–30 с на 70 страниц):
   - номера страниц в оглавлении (по закладкам PDF);
   - таблица, не влезшая на страницу, режется на части: «Продолжение таблицы N», шапка повторяется, нижняя линия на разрыве не рисуется;
   - заголовок подраздела, после которого на странице осталось меньше трёх строк, переносится на новую страницу;
   - если последняя строка абзаца — одно слово, абзац уплотняется на 0,2–0,3 pt (методичка разрешает до 0,3);
   - рисунок, уехавший на следующую страницу и оставивший дыру, уменьшается (не меньше 70 %), если так он помещается;
   - что не лечится автоматически, уходит в отчёт со страницей и строкой исходника: рисунок в начале страницы, большое пустое место, объём введения/заключения/работы.

**Что печатать.** Разбиение на страницы проверено в LibreOffice. Шрифты Liberation метрически совпадают с Times New Roman, поэтому Word почти всегда разбивает так же. Но переносы слов у Word свои, и абзац может сдвинуться на строку. Печатать и сдавать на переплёт надёжнее из `vkr.pdf`; `vkr.docx` — для электронной сдачи. Править docx руками не стоит: разрезы таблиц и номера страниц в оглавлении зафиксированы при сборке. Всё правится в исходниках, затем пересборка.

## Структура

```
vkr/
  parser.py, inline.py   Markdown-подмножество → модель с номерами строк
  typo.py, fixsrc.py     типографика (в модели при сборке; в исходнике — vkr fix)
  numbering.py, bib.py   нумерация, ссылки, описания источников по ГОСТ
  validate.py            правила класса «вход»
  builder.py             docx (python-docx + OOXML в порядке схемы)
  layout.py              цикл вёрстки через LibreOffice + PyMuPDF
  math_omml.py           LaTeX → формулы Word через pandoc
  profiles/pgu-povt.yaml шапка вуза, кафедра, зав. кафедрой, направление
  docs/                  RULES.md, FORMAT.md, CLAUDE.md и .claude/ для шаблона проекта
tools/
  import_docx.py         перенос готового docx в формат vkr (так проверялось на дипломе Гончарука)
  check_order.py         проверка порядка OOXML-элементов (Word к нему строг)
```
